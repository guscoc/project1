# 장바구니 구매 전환 예측과 개인화 프로모션 전략

**한 줄 제안:** 담아둔 상품의 구매 전환과 구매 시점을 분석하고, 고객별 쿠폰·리마인드·추천의 대상과 시점을 제안한다.

**상태:** 상세 기획. 공개 자료의 배포 경로와 선행연구를 조사했으며 실제 파일 수집·모형 학습·운영 실험은 미실시다.

## 1 문제 정의 및 분석 목표

### 문제와 의사결정

장바구니는 결제 후보를 담는 공간이지만 관심 저장·가격 비교 등 여러 목적으로 쓰일 수 있다. 오래 보관한 고객에게 같은 할인 혜택을 지급하면 원래 구매할 고객에게도 비용이 발생할 수 있다. 보관 기간만으로 구매 포기 이유나 할인 효과를 단정하기 어렵다.

분석 결과로 바꿀 결정은 **누구에게, 담은 뒤 어느 시점에, 어떤 개입을 제공할 것인가**다. 사용자 목적과 실제 불편은 초기 인터뷰·자료 점검에서 확인한다.

### 대상과 질문

분석 대상은 고객·상품·담기 구간과 정해진 의사결정 시점이다. 예를 들어 ‘담은 지 3일째까지 구매하지 않은 고객의 이후 7일 내 동일 상품 구매’를 정의할 수 있다. 3일·7일·5%는 후보 조건이며 자료와 업무 목적을 확인한 뒤 확정한다.

| 연구 질문 | 분석 목표 | 평가·판단 |
| --- | --- | --- |
| 어떤 상황에서 구매 전환이 낮거나 지연되는가? | 기간·상품·가격대·사전 이용 이력·장바구니 구성별 비교 | 전환과 구매까지의 시간, 고객군별 불확실성 |
| 이후 구매 가능성을 예측할 수 있는가? | 의사결정 시점 이전 정보로 예측 | 기준모형 대비 성능·확률 보정·고객군 오류 |
| 언제 누구에게 개입할 것인가? | 예측과 비용·업무 조건을 연결해 후보 전략 설계 | 적용 대상·시점·제외 규칙의 명확성 |
| 개입이 추가 구매와 가치를 만드는가? | 무작위 비교의 설계, 자료 확보 시 실행 | 전체 배정 고객 기준 추가 구매·비용·부작용 |

구매할 가능성과 쿠폰으로 추가 구매할 가능성은 서로 다른 목표다. 공개 관찰 자료의 구매 예측만으로 개입 효과를 학습했다고 표현하지 않는다.

## 2 제안 시스템과 수행 범위

| 상황 | 실행 후보 | 1차 프로젝트에서의 위치 |
| --- | --- | --- |
| 일정 기간 담기 후 구매 미관찰 | 리마인드 또는 대상 상품 5% 쿠폰 | 개입 한 가지의 검증 계획 |
| 상품을 반복 조회하지만 구매 미관찰 | 형태·가격대가 비슷한 대체 상품 | 후속 확장 |
| 다른 고객의 선택을 참고 | 같은 상품을 담았던 고객들의 이후 구매 상품 | 후속 확장 |
| 관심상품을 별도로 저장 | 위시리스트와 공개 선택 목록 탐색 | 별도 저장 기록 확보 후 확장 |

**최소 완성 범위:** 자료 채택 → SQL 분석 테이블 → 전환·시간 분석 → 구매 예측 → 프로모션 대상·시점과 실험 설계 → 결과·한계·실행 제안.

실제 구매·추가 이익의 인과효과 검증은 운영 협업이나 무작위 개입 자료를 확보했을 때 추가한다. 공개 과거 로그만으로도 수행 가능한 범위를 기본 계획으로 삼는다.

## 3 데이터 수집 가능성

| 후보·필요 자료 | 확인한 상태 | 채택 전에 확인할 것 |
| --- | --- | --- |
| REES46 marketplace | 공식 월별 원본 링크 확인 | 패션 표본, 실제 이벤트·필드·추적 기간·ID 연결 |
| Google 전자상거래 샘플 | 공식 설명과 담기·구매 쿼리 확인 | 의류 범위, 익명화·결측·연결 일관성 |
| 프로모션 배정·노출·거래 | 미확보 | 운영 협업과 고객 단위 배정·결과 연결 |
| 할인·취소·반품·변동비 | 미확보 | 비용 정의와 관찰 기간 |

현재는 **배포 경로 확인 완료, 실제 파일·패션 표본 검증 전**이다. 초기 단계에 소규모 파일을 읽고 동일 고객·상품의 담기→구매를 구성할 수 있는지 확인한다. [출처와 확보 현황](../../docs/data-access-status.md)

필수 데이터가 부족하면 다른 자료를 점검한다. 패션 표본이 부족한 일반 전자상거래 분석은 패션 분석의 완성 결과와 구분한다. 삭제 기록이 없으면 ‘현재 장바구니에 남아 있음’ 대신 ‘담기 이후 구매 미관찰’로 대상을 정의한다.

## 4 선행연구와 이번 프로젝트의 기여

장바구니 구성과 이탈, 비용 제약을 고려한 프로모션 개인화, 할인 비용을 반영한 추가 이익을 다룬 연구를 참고한다. 연구마다 업종·자료·실험 환경이 달라 결과를 그대로 패션에 옮기지 않는다. [선행연구 3편 비교](related-work.md)

이번 프로젝트의 기여는 **분석 대상과 시간을 직접 정의하고, 구매 예측·고객군·비용·실험을 연결하는 재현 가능한 패션 적용 설계**다. 새로운 알고리즘 개발이나 실제 쿠폰 효과 입증을 사전 성과로 제시하지 않는다.

## 5 SQL Python 및 분석 과정

1. **정의:** 고객·상품·담기 구간·기준 시각·구매·관찰 기간을 고정한다.
2. **SQL:** 중복 이벤트, 반복 담기, 시각 순서, 구매·삭제를 정리하고 사전 특성을 연결한다.
3. **기초 분석:** 기간별 누적 구매 전환, 구매까지의 시간, 고객군·상품·장바구니 구성 차이를 비교한다.
4. **예측:** 기준모형과 비교모형을 시간 순서로 평가하고 예측확률의 신뢰성과 오류를 보고한다.
5. **실행:** 대상·시점·혜택·제외 규칙·예상 비용과 검증 계획을 제안한다.

예측 시점 이후 행동을 입력에 넣지 않고 학습 결과의 관찰도 평가 시작 전에 끝나도록 구간을 분리한다. 담기 구간과 주문이 여러 번 존재하면 한 구매를 여러 성공으로 중복 집계하지 않게 규칙을 둔다. [데이터·분석 상세](data-and-experiment.md)

## 6 Usable Feasible Valuable 평가

| 기준 | 확인할 질문 | 증거와 완료 조건 | 현재 판단 |
| --- | --- | --- | --- |
| **Usable 가용성** | 분석 결과로 대상·시점·행동을 정할 수 있는가? | 입력 가능한 필드와 대상·제외·시점·행동을 명시한 캠페인 의사결정표 | 설계 가능, 실제 필드 확인 필요 |
| **Feasible 실행 가능성** | 연결 가능한 패션 로그와 평가 기간·자원이 있는가? | 파일 파싱·연결·표본·관찰 기간·처리 시간·메모리 점검 통과 | 조건부, 첫 2주에 채택 판단 |

데이터 품질 기준은 첫 표본 조사에서 정한다. 예측의 검출 목표와 실용적인 적용 기준, 실험의 최소 개선폭·표본 수는 결과를 보기 전에 근거와 함께 확정한다.

## 7 개입 실험과 평가

고객별 대표 대상 상품을 배정 전에 고정하고, 같은 조건의 고객을 무개입과 개입 집단에 무작위 배정한다. 첫 실험은 쿠폰 또는 리마인드 한 개입을 비교한다.

주 지표는 전체 배정 고객 중 정해진 기간 내 대상 상품을 구매한 비율이다. 전체 상품 구매·구매액·취소·반품·비용도 함께 봐서 상품 대체나 비용 증가를 확인한다. 쿠폰 사용 고객만 남겨 비교하지 않는다.

예측 성능이 좋아도 개입 효과가 입증된 것은 아니다. 운영 실험이 없으면 결과물의 상태를 ‘실험 설계’로 표시한다. 손익 자료가 없을 때의 가정별 계산은 실제 이익과 구분한다. [지표·표본·판단 규칙](data-and-experiment.md)
